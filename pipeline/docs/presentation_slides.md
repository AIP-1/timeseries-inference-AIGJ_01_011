## 1. 교육장 CO₂를 60분 먼저 읽는다
- team4 · 팀 Jetson(Orin Nano Super 8GB)에서 2주째 상시 운영 중
- 센서(CO₂·온도·습도)만으로 "지금 어떤가, 60분 뒤 어떻게 될까"
- 무엇이 됐고, 무엇이 안 됐고, 왜 그런지

## 2. 구조
- 수집기 → 학습(같은 전처리 코드) → ONNX → 추론 서비스 → MQTT · API(:8000)
- 수집: 2주 커버율 99.1~99.8%. 그동안 재부팅 4번에도 결측 최대 7분. 브로커를 껐다 켜면 12초 만에 재수집
- 서비스: 매분 예측·이상 탐지·사용 여부·환기 경보, 처리 2.4초

## 3. 데이터
- 키트를 못 받아 **합성 데이터 생성기를 직접 만듦**. 시간표에 따라 CO₂가 물리적으로 변하고, 고장 10건이 들어 있음
- 실데이터 14개월(학원 InfluxDB)로 과제 2·3·6·7·8을 다시 함
- 실제 시간표 없음 → 학습 기간 CO₂로 추정

## 4. 결과표
| 기준 | 결과 |

| 이상 탐지 80% · 헛경보 1회/일 (합성) | 90% · 0.43회 ✅ |

## 5. 가장 의외였던 발견: 예측을 가른 건 시간표
- 일정 정보의 효과: 합성(진짜 시간표) **-27%** vs 실데이터(추정 시간표) **-4%**
- 모델을 바꾼 효과(GRU·LSTM·TCN): 4ppm 안팎, 앙상블로 3ppm
- 실데이터 오차는 아침 8시에 몰림: 98.6ppm. 이 시각에는 현재값 유지(77.8)보다도 나쁨

## 6. 하루 들여다보기 (10-14)
- 사무실: 아침 상승·오후 고점을 기준선보다 먼저 따라감
- 실습실: 1,150ppm을 예측했지만 실제는 820에서 멈춤
- 회의실: 아무도 없었는데 1,160ppm 헛예측
- → 평소 패턴은 배웠지만, 오늘 수업·회의가 있는지는 모름

## 7. 이상 탐지 · 환기 경보
- 오토인코더(냉방 정지) + 규칙(튄 값·값 고정) + 예측 오차(환기 정지) → 10건 중 10건
- 새벽 영점 틀어짐 규칙: 실데이터 새벽 상위 1%로 다시 맞춤
- 실운영 2주: 1,000ppm 초과 25건 중 **24건에 10분 이상 먼저 경보**. 하지만 정밀도 8~31%라 헛경보가 많음

## 8. 엣지 최적화의 함정
- ONNX Runtime CPU 0.32ms가 가장 빠름(작은 모델은 호출 비용이 대부분), 서비스 RSS 112MB
- TensorRT FP16: GRU에서 반올림 오차가 쌓여 1.48ppm
- 'FP32' 엔진도 1ppm: Orin이 행렬 곱을 **TF32**로 함 → `--noTF32`로 0.001ppm
- INT8: 빨라지지 않고 예측 오차 6ppm → 쓰지 않음
